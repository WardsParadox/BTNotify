# Apple app icon guidance for macOS 27

Verified against public Apple sources on November 10, 2026. Research only; no application was launched.

## Conclusion for BTNotify

**A layered Icon Composer `.icon` is recommended, not required.** Apple's current Human Interface Guidelines explicitly accept either nonlayered bitmap images such as PNG or layered Icon Composer files for macOS. They recommend Icon Composer for control over Liquid Glass effects and appearance variants. A PNG appiconset is therefore still a supported approach; adopting `.icon` is a design-quality choice, not a demonstrated macOS 27 compatibility requirement. [1]

For BTNotify's white headphones and battery on blue, a sensible modernization is to preserve those recognizable shapes, make the blue background a Composer fill, and supply headphones and battery as separate foreground artwork. This is an application of Apple's general guidance, not an Apple requirement for this particular icon. A Composer migration should remove the existing baked-in rounded-square boundary from source layers and let the system apply the enclosure mask. [1][2]

## What is explicitly verified for version 27

- Apple's public **macOS 27 Golden Gate Release Notes** identify macOS 27 and the SDK bundled with Xcode 27. macOS 27 is explicitly documented; the guidance below does not depend on inferring its existence from macOS 26 documentation. These release notes do not state that an Icon Composer file is mandatory. [3]
- The current Icon Composer article explicitly describes comparing **macOS 26 with macOS 27** rendering using the Effects buttons. [2, “Simulate device backgrounds, effects, and lighting”]
- The same article states that **before version 27**, selecting Inside or Outside specular highlights simply enables highlights, and **Refraction settings have no visible effect**. Therefore precise inside/outside highlight placement and refraction are verified version-dependent capabilities. [2, “Apply Liquid Glass effects to groups and layers”]
- Xcode 27 release notes describe Icon Composer 2.0's sharper rendering mode, refractivity, outside specular, and deeper shadows, and recommend previewing both design generations before adding the icon to a project. Their text calls the target releases “upcoming 2027 operating systems”; this is Apple's wording, not a separately verified release-date claim. [4]
- The HIG change log dates its **format-options guidance to October 28, 2026**, and its revised Liquid Glass guidance to June 8, 2026. The current explicit PNG alternative is recent guidance, not merely a legacy allowance inferred from WWDC25. [1]

## Current general Apple rules that apply to macOS

| Topic | Verified guidance |
| --- | --- |
| Source format | Either PNG/nonlayered bitmap or layered Icon Composer; Composer offers more flexibility and control. With a bitmap, the system attempts to separate foreground from background into two layers. [1, “Icon formats”] |
| Segmentation limits | Automatic Liquid Glass effects apply to large, simple foreground shapes; smaller complex elements, text, and thin lines do not automatically receive those effects. Composer lets the author control which elements receive them. [1] |
| Shape and size | macOS source layout is square, **1024 × 1024 px**, with system-applied rounded-square masking and automatic smaller variants. [1, “Specifications”] |
| Masking | Supply unmasked square layers. Pre-masking the enclosure can harm specular highlights and produce jagged edges. Center important content to avoid clipping. This does not forbid curved shapes within the artwork itself. [1, “Icon shape”; 2] |
| Background | Prefer a simple solid color or gradient. Composer can create both. An imported background must be **full-bleed and opaque**. Foreground layers can contain transparency; this is not a blanket ban on alpha throughout the icon. [1, “Layer design”] |
| Effects | Let the system supply highlights, interlayer shadows, blurring, and related effects. Avoid baking these into source layers unless deliberately tested with system rendering. [1, “Visual effects”; 2] |
| Artwork | Prefer scalable vectors; the Composer workflow documents SVG, with PNG for raster artwork or unsupported SVG features. Avoid fine detail and extremely thin lines at small sizes. [1][2] |
| Appearances | Preview default, dark, and mono; mono includes clear and tinted variants. Keep the core design consistent across appearances. Missing variants can be generated by the system. [1][2] |

These are current cross-platform HIG rules, not claims that every rule was newly introduced in macOS 27. WWDC25 explains the original layered Liquid Glass workflow and supports the background/masking advice, but cannot independently establish new macOS 27 requirements. [5][6]

## Compatibility and Xcode integration

- Add the `.icon` file directly to the Xcode project and set the target's App Icon name to its filename without the extension. It is not a PNG export placed inside the existing appiconset. [2, “Add your Icon Composer file to an Xcode project”]
- Xcode uses the Icon Composer file in preference to the existing app icon asset catalog. Apple says it automatically generates similar-looking images at build time for older deployment targets without the newer rendering/appearance support. [2, “Overview”]
- Consequently, keeping an old appiconset alongside `.icon` does **not** promise the old artwork remains the actual icon on older macOS versions. Apple explicitly advises continuing to use asset catalogs if preserving that existing icon on previous releases is the requirement. [2]
- Composer's flattened export is described as useful for marketing and communication; it does not preserve layered runtime behavior. [7]
- The current standalone Composer download requires **macOS Tahoe 26.4 or later** to run the authoring tool. That requirement is distinct from the deployment compatibility of the generated app icon. [7]

## Official layered example; schema limits

Apple's [Landmarks sample page][8] explicitly includes an Icon Composer app icon. Its documentation metadata links the official [sample ZIP][9]. The downloaded archive was inspected without launching an app:

```text
Landmarks/Landmarks/Resources/Landmarks App Icon.icon/
  icon.json
  Assets/landmarks-app-icon-layer-1.svg
  Assets/landmarks-app-icon-layer-2.svg
  Assets/landmarks-app-icon-layer-3.svg
  Assets/landmarks-app-icon-layer-4.svg
  Assets/landmarks-app-icon-layer-5.svg
```

Its `icon.json` provides a concrete Apple-authored example of `fill`, `groups`, group `layers`, layer `image-name`, `glass`, `opacity`, appearance `fill-specializations`, group `shadow`/`translucency`, and `supported-platforms`. The sample uses `supported-platforms.squares: "shared"`; a Mac-only document should follow the installed Mac template rather than assuming that value is mandatory.

No formal public JSON schema or guarantee of stable hand-authored keys was found in the sources reviewed. The official sample is evidence of a working format example, not a specification for every supported field or the new generation-27 effect keys. Validate a generated file with the installed Apple toolchain.

## Bluetooth artwork revision

The app icon now uses `Bluetooth.svg` and `Notification.svg` (original notification dot), replacing headphones/battery. The menu bar draws the simplified Bluetooth vector in Swift and overlays the actual `app.badge` SF Symbol. Apple explicitly prohibits SF Symbols or confusingly similar images in app icons/logos; the SF Symbol is therefore used only in UI. Source: [HIG: SF Symbols](https://developer.apple.com/design/human-interface-guidelines/sf-symbols). No GUI was launched during verification.

## Complete appearance verification

The Bluetooth icon now explicitly supplies default and dark colors plus a white monochrome source through `fill-specializations` (`dark` and `tinted`). The notification group disables translucency for legibility. Apple's renderer generates Default, Dark, TintedLight, TintedDark, ClearLight, and ClearDark; all six generation-27 exports were visually checked together in `.build/icon-previews/AllAppearances.png`. The ten macOS PNG slots are refreshed from the 1024px Default export, with dimensions verified. The PNG set does not encode the six system appearances: the layered `.icon` document provides them. Build and signature checks pass; compiled Assets.car contains the Bluetooth/Notification vectors and Aqua, DarkAqua, and Tintable image stacks. Clear and tinted light/dark are rendering modes of the monochrome source. No GUI was launched.

## Current Bluetooth-and-bell identity

`Notification.svg` now contains an original bell outline rather than the earlier dot. The same geometry is used by the native menu bar renderer. Default and Dark retain the blue gradients; all six appearances were regenerated and checked. The menu bar uses a template image while idle and a non-template image with a system-accent bell after a notification request is accepted. The bell clears when the menu is opened or a notification is clicked.

Device rows read installed artwork from `/System/Library/PrivateFrameworks/CoreBluetoothUI.framework` through Foundation/AppKit resource APIs. The installed Bluetooth Settings extension links this framework; its `AssetPaths.plist` maps product IDs to device images and clone entries. This establishes shared shipped artwork, not a runtime trace of Settings' image-selection call. Power-source Apple vendor/product metadata supplies model IDs; family images and SF Symbols are fallbacks. No framework code is explicitly loaded or linked for these images, and no artwork is copied into the app. Resource names are an OS implementation detail and may change. Offscreen checks resolved nine device-family images plus a keyboard model image on the tested installation.

## App icon restoration in 0.1.5

The app icon has been restored to the previous Bluetooth mark, red notification dot, and blue gradients at the user's request. The menu bar retains its separate outline/accent bell. All six app icon appearances and ten PNG sizes were regenerated from the restored Composer sources.
